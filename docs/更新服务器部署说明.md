## 发布新版本

以下流程适用于 Windows 开发机向当前更新服务器发布安装包。发布时必须使用严格递增的版本号，例如 `1.1.7` 后只能发布 `1.1.8`；不要用同一个版本号覆盖已发布版本，否则客户端不会认为存在更新。

### 1. 修改版本号

编辑 `app/package.json`，修改 `version` 字段：

```json
"version": "1.2.0"
```

### 2. 构建安装包

```powershell
Set-Location "D:\ruanjianproject\pi Agent\app"
npm run dist
```

构建产物位于 `app/dist/`：

| 文件 | 说明 |
|---|---|
| `苹果Pi Setup X.X.X.exe` | NSIS 安装包 |
| `苹果Pi Setup X.X.X.exe.blockmap` | 增量更新校验文件，必须与安装包一起上传 |
| `latest.yml` | 自动更新清单（版本号、SHA512、下载 URL），必须最后上传 |

### 3. 检查本地构建结果

在上传前确认三个文件存在，且 `latest.yml` 中的版本号、安装包文件名和当前准备发布的版本一致。以发布 `1.2.0` 为例：

```powershell
Get-Item `
  "dist\苹果Pi Setup 1.2.0.exe", `
  "dist\苹果Pi Setup 1.2.0.exe.blockmap", `
  "dist\latest.yml"

Get-Content -Raw -Encoding UTF8 "dist\latest.yml"
```

### 4. 上传安装包和 blockmap

先上传安装包与 `.blockmap`，不要先上传 `latest.yml`。这样在线客户端在任何时刻读取更新清单，都只会看到一个可下载的完整版本。

```powershell
scp.exe -o BatchMode=yes `
  "dist\苹果Pi Setup 1.2.0.exe" `
  "dist\苹果Pi Setup 1.2.0.exe.blockmap" `
  "root@47.93.10.125:/var/www/html/apple-pi/updates/"
```

### 5. 验证安装包上传完整

比较本地与服务器上的 SHA-256。两项哈希必须完全一致，才可以发布新的 `latest.yml`：

```powershell
$localHash = (Get-FileHash -Algorithm SHA256 "dist\苹果Pi Setup 1.2.0.exe").Hash.ToLower()
$remoteHash = (ssh.exe -o BatchMode=yes root@47.93.10.125 "sha256sum '/var/www/html/apple-pi/updates/苹果Pi Setup 1.2.0.exe'").Split()[0].ToLower()

"Local:  $localHash"
"Remote: $remoteHash"
if ($localHash -ne $remoteHash) { throw "安装包哈希不一致，停止发布" }
```

### 6. 最后发布更新清单

确认安装包无误后，再上传 `latest.yml`。此操作会使所有旧版本客户端立刻发现该更新：

```powershell
scp.exe -o BatchMode=yes `
  "dist\latest.yml" `
  "root@47.93.10.125:/var/www/html/apple-pi/updates/latest.yml"
```

### 7. 验证线上更新源

```powershell
curl.exe --fail --silent --show-error `
  "http://47.93.10.125/apple-pi/updates/latest.yml"

curl.exe --head --fail `
  "http://47.93.10.125/apple-pi/updates/%E8%8B%B9%E6%9E%9CPi%20Setup%201.2.0.exe"
```

第一条命令应返回 `version: 1.2.0`；第二条应返回 `200 OK`。随后在一台低于 `1.2.0` 的已安装客户端启动应用，确认会出现更新提示并能完整下载、安装。

> 发布过程不需要在命令中填写密码。请使用本机已配置的 SSH 密钥；不要将服务器账号密码写入本文档、脚本或版本库。

## 安装包自动保留

服务器通过 `apple-pi-release-prune.path` 监听更新目录。每次发布新的安装包或更新清单后，会按语义化版本号自动删除最旧的发布文件，只保留最新的 `10` 个安装包及各自的 `.blockmap`；`latest.yml` 始终保留。

安装脚本和 systemd 单元的源文件位于 `app/scripts/server/`。首次部署或服务器迁移时执行：

```powershell
Set-Location "D:\ruanjianproject\pi Agent\app"
scp.exe -o BatchMode=yes `
  "scripts\server\apple-pi-prune-releases.sh" `
  "scripts\server\apple-pi-release-prune.service" `
  "scripts\server\apple-pi-release-prune.path" `
  "root@47.93.10.125:/tmp/"

ssh.exe -o BatchMode=yes root@47.93.10.125 `
  "install -m 755 /tmp/apple-pi-prune-releases.sh /usr/local/sbin/apple-pi-prune-releases.sh && install -m 644 /tmp/apple-pi-release-prune.service /etc/systemd/system/apple-pi-release-prune.service && install -m 644 /tmp/apple-pi-release-prune.path /etc/systemd/system/apple-pi-release-prune.path && systemctl daemon-reload && systemctl enable --now apple-pi-release-prune.path && systemctl start apple-pi-release-prune.service"
```

验证状态：

```powershell
ssh.exe -o BatchMode=yes root@47.93.10.125 `
  "systemctl is-active apple-pi-release-prune.path && find /var/www/html/apple-pi/updates -maxdepth 1 -type f -name '*.exe' | wc -l"
```

### 发布失败或需要回滚

- 在上传 `latest.yml` 前失败：删除服务器上刚上传的同版本 `.exe` 和 `.blockmap`，客户端不会受到影响。
- 在 `latest.yml` 发布后发现安装包有问题：不要覆盖同一版本。应修复后提高版本号重新构建并按本流程发布，例如从 `1.2.0` 发布为 `1.2.1`。
- 历史安装包可以保留，便于审计；当前自动更新只读取 `latest.yml` 指向的版本。

## 必要更新（强制推送）

当需要所有用户强制安装某个版本时，在 `latest.yml` 的 `releaseNotes` 中加入 `[必要更新]` 或 `#必要更新#` 标记。

### 方式一：通过 electron-builder 配置

在 `app/package.json` 的 `build` 块中添加：

```json
"build": {
  "releaseInfo": {
    "releaseNotes": "[必要更新] 修复了严重的安全漏洞，所有用户必须立即更新。"
  }
}
```

构建后 `latest.yml` 会自动包含 `releaseNotes` 字段。

### 方式二：手动编辑 latest.yml

构建后直接编辑 `latest.yml`，添加 `releaseNotes` 字段：

```yaml
version: 1.2.0
files:
  - url: 苹果Pi Setup 1.2.0.exe
    sha512: xxxxxxx
    size: xxxxxx
path: 苹果Pi Setup 1.2.0.exe
sha512: xxxxxxx
releaseDate: '2026-07-29T00:00:00.000Z'
releaseNotes: "[必要更新] 修复了严重的安全漏洞，所有用户必须立即更新。"
```

### 必要更新的效果

- 用户**无法关闭**更新通知条（关闭按钮被隐藏）
- 无论用户是否开启了"停止更新推送"，此更新**必定弹出**
- 通知条变为**红色警告样式**以示区分
- 下载完成后**自动在退出时安装**

## 客户端配置

更新服务器地址在 `app/package.json` 的 `publish` 块中配置：

```json
"build": {
  "publish": {
    "provider": "generic",
    "url": "http://47.93.10.125/apple-pi/updates/"
  }
}
```

> 如果更换服务器 IP 或域名，需要同步修改此 URL。

## Nginx 配置参考

当前 Nginx 配置（位于 `/etc/nginx/sites-available/default`）：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    root /var/www/html;
    index index.html index.htm index.nginx-debian.html;
    server_name _;
    location /apple-pi/updates/ {
        alias /var/www/html/apple-pi/updates/;
        add_header Cache-Control "no-cache, must-revalidate";
        default_type application/octet-stream;
    }
    location / {
        try_files $uri $uri/ =404;
    }
}
```

修改配置后重载：

```bash
nginx -t && systemctl reload nginx
```

## 验证清单

发布后逐项确认：

- [ ] `curl http://47.93.10.125/apple-pi/updates/latest.yml` 返回最新版本号
- [ ] `curl -I http://47.93.10.125/apple-pi/updates/苹果Pi%20Setup%201.1.0.exe` 返回 `200 OK` 和 `application/octet-stream`
- [ ] 安装旧版本 → 启动应用 → 收到更新通知
- [ ] （必要更新）标记 `[必要更新]` 的版本无法关闭通知条

## 故障排查

| 问题 | 检查 |
|---|---|
| 客户端收不到更新 | `curl` 检查 `latest.yml` 是否最新；确认 `version` 大于客户端版本 |
| 下载 404 | 确认 `.exe` 文件名与 `latest.yml` 中的 `url` 完全一致（含空格和中文） |
| Nginx 502/503 | `systemctl status nginx`；`nginx -t` 检查配置 |
| 服务器端口不通 | `ufw status` 确认 80 端口开放；阿里云安全组规则确认 |
