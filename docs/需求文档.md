## 2. 背景与目标

### 2.1 背景

- LLM Coding Agent（Claude Code、OpenCode 等）已验证形态成熟，但闭源产品存在：供应商锁定、数据出境顾虑、定制能力受限、按量成本不可控等问题。
- 开源项目 Pi 提供了生产可用的三层底座（LLM 接入 / Agent 运行时 / CLI 应用），MIT 协议，支持 30+ 模型 Provider（含国内厂商与本地模型），适合作为自研 Agent 的技术底座。

### 2.2 产品目标

| # | 目标 | 衡量指标 |
|---|---|---|
| G1 | 基于 Pi 底座交付可用的自研 Agent 软件 MVP | 覆盖 P0 需求，内部试用 2 周无阻断性问题 |
| G2 | 多模型自由切换，支持国产模型与本地模型 | 至少接入 3 家 Provider（含 1 家国内 / 1 个本地 OpenAI 兼容端点） |
| G3 | 团队级定制能力（规范、技能、扩展） | 支持打包分发 1 个内部 Pi Package |
| G4 | 会话可追溯、成本可观测 | 会话完整持久化；每次会话展示 token/成本 |

### 2.3 非目标（本期不做）

- 不做自研 LLM；不做模型微调。
- 不做移动端；不做多人实时协作。
- 不内置 MCP 协议（遵循 Pi 设计哲学，需要时通过扩展接入）。
- 不做云端会话同步服务（会话存本地，后续版本再评估）。

## 3. 用户场景与用例

### 3.1 核心用户画像

| 角色 | 诉求 |
|---|---|
| 开发工程师 | 让 Agent 读写代码、跑命令、修 bug、写测试，过程中可打断纠偏 |
| 技术负责人 | 统一团队 Agent 使用规范（AGENTS.md、Skills），控制成本与密钥安全 |
| 运维/平台工程师 | 以脚本/RPC 方式把 Agent 嵌入 CI、工单系统等自动化流程 |

### 3.2 典型用例

- **UC-1 交互式编码**：开发者在项目目录启动 Agent，用自然语言要求"修复 `login.ts` 的类型错误并跑测试"，Agent 自动读文件 → 编辑 → 执行 `bash npm test` → 根据结果迭代，直至完成。
- **UC-2 过程打断与纠偏（Steering）**：Agent 执行过程中，开发者发现方向不对，直接输入补充指令，当前工具步骤结束后 Agent 按新指令调整。
- **UC-3 会话分支与回溯**：对同一问题尝试两种方案，通过会话树 fork 出分支互不影响；可随时 `/tree` 回跳查看历史。
- **UC-4 模型切换与降级**：默认用国产模型控制成本，遇到难题一键切换到更强的模型（跨 Provider Handoff，上下文无缝迁移）；公司内网环境切换为本地 OpenAI 兼容端点（Ollama/vLLM）。
- **UC-5 团队规范注入**：项目根目录放置 `AGENTS.md`（编码规范、目录约定）与 `.pi/SYSTEM.md`，团队成员启动 Agent 自动加载统一约束。
- **UC-6 自动化集成**：CI 中以 `pi -p`（print 模式）或 `--mode rpc`（JSONL）调用 Agent 完成代码审查、changelog 生成等无人值守任务。
- **UC-7 能力扩展**：通过内部 Pi Package 分发团队自研扩展（如：内部 API 查询工具、发布检查工具、权限门）。

## 4. 功能需求

> 优先级：**P0** = MVP 必须；**P1** = 首版重要；**P2** = 后续迭代。
> 说明：底座已具备的能力标注为【Pi 原生】，主要是集成、验证与少量定制；需自研的标注为【自研】。

### 4.1 Agent 核心能力

| ID | 需求 | 优先级 | 来源 | 验收标准 |
|---|---|---|---|---|
| FR-1.1 | 多轮对话与流式输出 | P0 | 【Pi 原生】pi-ai 统一流式事件 | 输出逐字流式渲染，无丢字/乱序 |
| FR-1.2 | 内置文件与命令工具：`read`/`write`/`edit`/`bash`/`grep`/`find`/`ls` | P0 | 【Pi 原生】 | 工具调用成功率 ≥ 99%（非模型原因失败可重试） |
| FR-1.3 | 工具执行并行/顺序控制 | P1 | 【Pi 原生】pi-agent-core executionMode | 默认并行；标记 sequential 的工具批顺序执行 |
| FR-1.4 | 执行中止与续跑（abort / continue） | P0 | 【Pi 原生】 | Esc 中止后上下文保留，可 continue 续跑 |
| FR-1.5 | Steering / Follow-up 消息队列 | P1 | 【Pi 原生】 | 工具运行期间可插队指令；结束后自动消费 follow-up 队列 |
| FR-1.6 | 自定义工具注册（Extension / SDK） | P0 | 【Pi 原生机制 + 自研工具】 | 按 TypeBox schema 注册新工具并在会话中可被模型调用 |
| FR-1.7 | 工具调用权限门（执行前确认/拦截） | P1 | 【自研】基于 `beforeToolCall` 钩子实现 | 高危工具（bash 写操作等）可配置为需人工确认；可整体 block |
| FR-1.8 | 上下文压缩（自动 + 手动 compact） | P1 | 【Pi 原生】 | 接近上下文上限时自动压缩且不丢任务目标；`/compact` 手动触发 |

### 4.2 模型接入

| ID | 需求 | 优先级 | 来源 | 验收标准 |
|---|---|---|---|---|
| FR-2.1 | 至少接入 3 个 LLM Provider | P0 | 【Pi 原生】pi-ai 30+ Provider | 配置 API Key 后 `/model` 可切换 |
| FR-2.2 | 支持国产模型（Moonshot/DeepSeek/MiniMax/智谱 等任选） | P0 | 【Pi 原生】 | 国产模型完成 UC-1 全流程 |
| FR-2.3 | 支持本地/内网 OpenAI 兼容端点（Ollama/vLLM/LM Studio） | P1 | 【Pi 原生】 | 断外网环境下本地模型可用 |
| FR-2.4 | 会话中途跨模型切换（Handoff） | P1 | 【Pi 原生】 | Claude → GPT → 国产模型切换，上下文不丢失 |
| FR-2.5 | Thinking/推理级别调节 | P2 | 【Pi 原生】 | Shift+Tab 循环级别；边框颜色有区分 |
| FR-2.6 | OAuth 订阅登录（Claude Pro/Max、ChatGPT Codex、GitHub Copilot） | P2 | 【Pi 原生】`models.login` | 个人订阅用户可无 API Key 登录 |
| FR-2.7 | Token 用量与成本展示 | P1 | 【Pi 原生】 | 底栏实时显示 token/缓存/成本/上下文占比 |

### 4.3 会话管理

| ID | 需求 | 优先级 | 来源 | 验收标准 |
|---|---|---|---|---|
| FR-3.1 | 会话本地持久化（JSONL，按项目目录组织） | P0 | 【Pi 原生】 | 重启后 `-c` 恢复最近会话 |
| FR-3.2 | 会话树（分支/fork/回跳/搜索/标签） | P1 | 【Pi 原生】 | UC-3 场景可操作 |
| FR-3.3 | 会话导出/分享（HTML/JSONL/私有 Gist） | P2 | 【Pi 原生】 | 导出文件可完整回看 |

|---|---|---|---|---|

## 5. 非功能需求

| ID | 类别 | 需求 | 指标/标准 |
|---|---|---|---|
| NFR-1 | 性能 | 首 token 延迟 | 取决于 Provider，本地 UI 渲染开销 < 100ms |
| NFR-2 | 性能 | 工具执行开销 | 运行时调度开销可忽略（工具本身耗时除外） |
| NFR-3 | 可靠性 | 流式中断恢复 | 网络中断/中止后上下文完整，可 continue 续跑 |
| NFR-4 | 可靠性 | 会话文件并发保护 | proper-lockfile 文件锁，多实例不互踩 |
| NFR-5 | 安全 | 密钥管理 | API Key 仅走环境变量/CredentialStore，不写入会话与日志；OAuth token 串行刷新 |
| NFR-6 | 安全 | 项目信任机制 | 未信任项目不加载其扩展（ask/always/never 可配） |
| NFR-7 | 安全 | 第三方扩展审计 | 内部 Pi Package 须走代码评审；文档明示扩展拥有完全系统权限 |
| NFR-8 | 合规 | 许可证 | Pi 系三包均为 MIT，可商用；保留版权声明 |
| NFR-9 | 可观测 | 用量统计 | 每次会话记录 token/成本；可选 OTel 导出 |
| NFR-10 | 兼容 | 运行环境 | Node.js LTS；Windows/macOS/Linux 终端 |
| NFR-11 | 可维护 | 版本跟随策略 | 跟踪上游 monorepo 版本（当前 0.81.1），每双周评估升级，API 变更走适配层 |
| NFR-12 | 离线 | 内网/离线可用 | `PI_OFFLINE` + 本地模型端点，断网可运行核心功能 |

## 6. 技术方案概要

- **集成路径**：采用技术文档第 6 节的 **路径 B（SDK 嵌入）为主、路径 A（扩展包）为辅**：
  - 以 `createAgentSession` + `ModelRuntime` + `SessionManager` 构建自有外壳（品牌、默认配置、内置扩展）；
  - 团队工具、权限门等以 Extension 形式开发，打包为内部 Pi Package（git/npm 分发）；
  - 自动化场景直接使用 `pi -p` 与 `--mode rpc`。
- **关键依赖**：TypeScript、Node.js、TypeBox、jiti（扩展加载）、pi-tui（终端 UI，可选）。
- **详细架构与 API**：见 [技术文档.md](./技术文档.md)。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 上游 API 变更（当前 0.x 版本，迭代快） | 高 | 依赖版本锁定 + 适配层隔离；双周评估升级；核心用法写自动化冒烟测试 |
| 模型 Provider 政策/价格变动 | 中 | 多 Provider 互备；国产 + 本地模型兜底 |
| 扩展安全（完全系统权限） | 中 | 内部包评审制度；项目信任默认 ask；高危操作走 FR-1.7 权限门 |
| 国产/本地模型工具调用能力差异 | 中 | pi-ai 仅收录支持 function calling 的模型；上线前对目标模型做 UC-1 全回归 |
| 密钥泄露 | 中 | 密钥不入库不落盘；OAuth 优先；提供密钥使用规范文档 |

## 9. 验收标准（MVP）

1. 安装自研包后，一条命令启动自有品牌 TUI，完成 UC-1 全流程（读→改→跑→迭代）。
2. 至少 3 个 Provider 可切换，其中含 1 家国产模型；会话中途切换上下文不丢。
3. 会话落盘、可恢复、可 fork；Esc 中止后可 continue。
4. `pi -p` 管道模式在 CI 脚本中跑通一个真实任务。
5. 内部扩展包通过 git 源安装成功，自定义工具被模型正确调用。
6. 权限门对高危 bash 命令弹出确认并可拦截。
7. 密钥不出现在任何会话文件与日志中（抽查）。
